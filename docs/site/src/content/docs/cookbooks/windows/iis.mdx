---
title: Windows IIS handoff
description: Move a local Windows IIS binding behind Cadder and restore it later.
---

Cadder can proxy a local IIS site through its Caddy front door. Use a disposable IIS binding first. Do not test this on a production IIS site.

## Requirements

- Windows with IIS and the PowerShell `WebAdministration` module available.
- A normal user shell for `cadderd`, `cadder`, and any `caddy` shim process used for the smoke test.
- Permission to approve a Windows administrator prompt when Cadder needs to mutate IIS bindings.
- A supported IIS binding: `http` on port `80` or `https` on port `443`.
- One route host for the binding.

Cadder keeps discovery, route planning, restore metadata, Caddy config changes, and operator operation in the normal user context. Only IIS binding changes are elevated.

## Hand Off A Binding

1. Start `cadderd` from the normal user shell, or run `cadder daemon start`.
2. Inspect IIS bindings:

```powershell
cadder iis bindings
```

3. Hand off the selected binding:

```powershell
cadder iis handoff <binding-id> --route-host iis-app.localhost
```

You can also use `cadder tui` for the same flow through the interactive operator surface.

Cadder stores restore metadata before it changes IIS. It then creates a loopback backend binding on the same IIS site, removes the public IIS binding, adds a Caddy reverse-proxy route for the route host, and applies the generated Caddy config.

If you deny the administrator prompt, Cadder reports the denied steps and leaves the original IIS binding available.

## Verify Routing

Use the original host or URL through Caddy:

```powershell
curl.exe -k -I https://iis-app.localhost/legacy/status
```

A routing smoke passes when the response goes through Caddy and reaches IIS. For an IIS application that is missing local configuration, an application-level `4xx` or `5xx` can still be a valid routing result.

## Restore A Binding

```powershell
cadder iis restore <binding-id>
```

Restore removes the Caddy IIS proxy route, recreates the original IIS binding from stored metadata, removes the loopback backend binding, and clears metadata after restore succeeds.

## Troubleshooting

- `Elevation denied`: approve the Windows prompt and retry when you are ready.
- `Insufficient privileges`: verify the account can manage the disposable IIS binding.
- `Missing route host`: pass `--route-host <host>`.
- `Missing TLS certificate`: repair the IIS HTTPS binding certificate, confirm IIS discovery can read it, then retry.
- `Unsupported binding shape`: leave the binding under IIS, or change it to a supported `http:80` or `https:443` binding first.
- `Conflict`: another IIS binding or active Cadder domain already uses the same route host.
- `Rollback failed` or `Restore failed`: keep the runtime metadata, fix the IIS permission or binding problem, then retry restore.
