## What You Need

- A real Caddy binary installed somewhere on your machine.
- A Cadder runtime installer or portable runtime archive for your OS from [GitHub Releases](https://github.com/MrMaxie/cadder/releases/latest).
- A project with a `Caddyfile`.

See [Releases and downloads](../../reference/releases/) if you are deciding between the native runtime installer and portable runtime archive.

## Configure Real Caddy

Create `cadder.toml` next to the Cadder binaries and set the real Caddy command there. See [cadder.toml](../../user-guide/cadder-toml/) for Windows path syntax, project overrides, environment aliases, and the full set of supported command forms.

## Run A Project

```sh
cadderd
cadder daemon status
caddy run
```

The shim attaches to `cadderd`, registers the project Caddyfile, and keeps that registration alive while the command is running. If the backend is unavailable, Cadder tries to start the missing daemon and then prints recovery steps if startup or attach fails. It does not run `caddy run` as an unmanaged real Caddy fallback.

Inspect Cadder with CLI or TUI:

```sh
cadder entrypoints list --output json
cadder logs show --limit 20 domain app.localhost --registration shim-1
cadder tui
```

`cadder tui` starts the interactive operator surface.
