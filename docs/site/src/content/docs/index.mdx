## What Cadder adds around Caddy.

<div class="cadder-capabilities">
  <article>
    <span>01</span>
    <div><h3>Keep projects independent.</h3><p>Each project keeps its own <strong class="cadder-key-term">Caddyfile</strong>. <code>caddy run</code> registers it with <strong class="cadder-key-term">Cadder</strong>.</p></div>
  </article>
  <article>
    <span>02</span>
    <div><h3>Reject collisions.</h3><p><strong class="cadder-key-term">Cadder</strong> checks route ownership and blocks conflicting active addresses before applying a change.</p></div>
  </article>
  <article>
    <span>03</span>
    <div><h3>See the complete picture.</h3><p><strong class="cadder-key-term">Cadder</strong> connects projects, local addresses, ports, logs, and <strong class="cadder-key-term">Caddy</strong> state in one view.</p></div>
  </article>
  <article>
    <span>04</span>
    <div><h3>Change one route at a time.</h3><p>Enable or disable one domain while unrelated local routes stay active.</p></div>
  </article>
</div>

## How to start.

Each project can define its own reverse-proxy route. <strong class="cadder-key-term">Cadder</strong> combines the active routes and keeps one shared <strong class="cadder-key-term">Caddy</strong> process synchronized.

The <a class="cadder-inline-link" href="https://caddyserver.com/docs/caddyfile">Caddyfile</a> format belongs to <strong class="cadder-key-term">Caddy</strong>: Caddy defines it and turns it into server configuration. <strong class="cadder-key-term">Cadder</strong> reads that result only to coordinate the local address with the right app port.

<div class="cadder-caddyfile-example" aria-label="Caddyfile example">
  <div class="caddyfile-header">
    <span class="caddyfile-label">Caddyfile</span>

  <pre><code id="caddyfile-example-code"><span class="caddyfile-address">shop.localhost</span> <span class="caddyfile-brace">&#123;</span>

<span class="caddyfile-brace">&#125;</span></code></pre>
</div>

Then run this command inside that project:

<CopyableCommand command="caddy run" label="Register this Caddyfile with Cadder" />

The route appears in `cadder tui`, where you can inspect its owner, target, and activation state.
