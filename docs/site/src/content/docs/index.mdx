Cadder combines local Caddy routes behind one real Caddy process owned by a per-installation daemon.

- `cadderd` owns runtime state, SQLite storage, IPC, and real Caddy.
- `caddy` is the PATH-facing shim used by existing `caddy run` workflows.
- `cadder` provides a routes-first TUI with contextual logs and lifecycle controls.

All three executables must come from the same 1.0 release. The exact protocol handshake rejects mixed versions before changing state.
